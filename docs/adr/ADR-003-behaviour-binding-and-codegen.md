# ADR-003 — Behaviour binding (handlers, variables) and code generation style

- **Status:** Accepted (Step 02 UAT) · **Date:** 2026-10-05 · **Step:** 02

## Context
GUIs need events and data. Embedding Python code in `.ui` files mixes concerns and is a security risk when opening third-party files. Generated code must not overwrite user code.

## Decision
- **Named handlers:** `<event name="command" handler="on_sign_in"/>`. `load_ui(path, handlers=obj)` connects to `getattr(obj, name)`. A missing handler raises a clear error by default (`strict=True`), or logs a warning with `strict=False`.
- **Named variables:** `<var id type default>` (string, int, double, bool) → tk `StringVar`/`IntVar`/`DoubleVar`/`BooleanVar`; on PySide6, a small `Observable` wrapper connected to widget signals. Exposed as `ui.vars.<id>`.
- **No inline code** in `.ui` files (Won't v1). Opening a `.ui` never executes code, except installed plugin widgets (ADR-004).
- **Codegen = composition** (pyuic style): `pyguibud-uic login.ui -o login_ui.py` produces `class Ui_Main: def setup_ui(self, root, handlers)`. The user's own `App` class owns `self.ui` and implements the handlers. `--stubs` additionally emits an `app_stub.py` with empty handler methods, written only if the file does not exist yet.
- Generated files start with a "do not edit — generated by pyguibud-uic" header and contain no PyGUIbud import. Strings are wrapped in `_()`.

## Consequences
- ➕ Regenerating is always safe; `.ui` files are safe to open; same API for runtime and codegen.
- ➖ Users write the handler bodies in Python, which is intended.
