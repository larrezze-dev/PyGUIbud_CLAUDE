# Spec — Step 11: code generator `pyguibud-uic`

- **Status:** Proposed (architect, 2026-10-06) · **ADRs:** 003 (amended by **008**), 005, 006, 007
- **UAT (plan row 11):** `pyguibud-uic examples/hello.ui -o hello.py` → `python hello.py` works **without** pyguibud installed (§11).
- **Pinned surface:** `docs/specs/runtime.md` §2.2. The generated class reproduces it. Every deviation is listed in §3.6.

## 0. Scope and budget
Target: **≤ 1,100 lines of production code** (tests and examples excluded).

| Module | New/changed | Budget |
|---|---|---|
| `src/pyguibud/codegen/__init__.py` | public API (§2) | 60 |
| `src/pyguibud/codegen/_support.py` | support code copied verbatim into every generated module (§4) | 300 |
| `src/pyguibud/codegen/_plan.py` | generation-time include expansion and component numbering (§5) | 90 |
| `src/pyguibud/codegen/_emit.py` | the Python writer: literal and identifier gates, straight-line build (§5–6) | 420 |
| `src/pyguibud/codegen/_pot.py` | `extract_pot` (§8) | 110 |
| `src/pyguibud/backends/_tkmap.py` | **move** the pure tables out of `_tk.py` (behaviour-neutral, §1) | ±0 |
| `src/pyguibud/core/files.py` | factor out the pure `probe_bytes` (§4.4) | 15 |
| `src/pyguibud/uic.py` | generation, `-o`, `--force`, `--extract` (§7) | 130 |
| `examples/hello_app.py`, `examples/hello_ui.py` (generated) | UAT (§11) | 70 |

**Must-ship path:** `examples/hello.ui`, plus the §10 fixtures (includes, images, dialogs, every event kind).
**Trim order if over budget:** (1) `--force` (always refuse to overwrite a non-generated file); (2) transcoding PPM/PGM to PNG (§4.4 fallback; refuse PPM/PGM in codegen instead).

## 1. Dependency rules
- `pyguibud.codegen` may import `pyguibud.core`, `pyguibud.i18n` and `pyguibud.backends._tkmap` (pure).
- It must **never** import `pyguibud_runtime`, the designer, `tkinter` or `ttkbootstrap`, and it must never import `codegen._support`. The generator reads that file's **text**; only the tests import it.
- `pyguibud.uic` imports `pyguibud.codegen`. The ADR-007 boundary test gains a case: `import pyguibud.codegen` leaves `tkinter`, `ttkbootstrap`, `pyguibud_runtime` and `pyguibud.codegen._support` out of `sys.modules`.
- **`_tkmap.py`, the single source of the Tk mapping.** Move these from `_tk.py` with their names unchanged, and have `_tk.py` re-import them: `_SELECT`, `_ACTIVATE`, `_VAR_OPTION`, `_TRACE_VAR`, `_OPTION`, `_MNEMONIC`, `_TK_BASED`, `_PADDED`, `_BOOTSTYLE_RE`, `_BOOTSTYLE`, `event_wiring`, `clip_text`, `_ELLIPSIS`, and the msgids `_M_FALLBACK`/`_M_BOOTSTYLE`. Codegen evaluates these **at generation time** and emits the results as literals. Chord and key sequences come from `core.keys.tk_shortcut`/`tk_key_sequences`, called with both `aqua=False` and `aqua=True`.
- **Generated module:** imports only the stdlib (`base64`, `gettext`, `logging`, `os`, `re`, `sys`, `tkinter`, `types`, `argparse` in the `__main__` block, `collections.abc`) and `ttkbootstrap`. It must run on Python ≥ 3.10 (`requires-python`); `_support.py` is linted with ruff `py310`. It needs `ttkbootstrap>=2.2,<3`, which the header states.

## 2. Public API (`pyguibud.codegen`)
```python
GENERATED_MARKER: Final = "# Generated by pyguibud-uic"      # first line of every generated module
FORMAT: Final = 1                                             # bump when the generated shape changes

class CodegenError(PyGUIbudError):          # code "codegen.*", lazily translated (pyguibud catalogue)
    findings: tuple[Finding, ...]

def generate_python(result: ReadResult, path: str, *, output: str, allow_outside: bool = False) -> GeneratedModule
def extract_pot(results: Sequence[tuple[ReadResult, str]], *, base_dir: str) -> str
def default_output(path: str) -> str        # "dir/my-form.ui" -> "dir/my_form_ui.py"

@dataclass(frozen=True)
class GeneratedModule:
    text: str                               # LF newlines, UTF-8-safe, ends with "\n"
    class_name: str
    warnings: tuple[Finding, ...]           # validator warnings + codegen warnings (fallbacks, bootstyle)
```
- `generate_python` **validates by itself** and never trusts the caller. It calls `validate(result.document, default_registry(), source=…, positions=…, files=DiskFiles(path, result))`.
  - Any error → `CodegenError("codegen.invalid_document", findings=errors)`.
  - `result.read_only` (a newer MINOR) → `codegen.read_only`.
  - No main and no dialog window → `codegen.nothing_to_generate`.
- `output` is used only to compute the relative locale paths (§4.3). It never appears in the text.
- **The output does not depend on the CLI language, the machine, the CWD, the hash seed or the time.** All generated text is fixed English plus `repr()` literals. Translated messages are only `Finding`/`CodegenError` messages, which go to stderr and never into the file.

## 3. Generated module shape (decision C1: support code + straight-line build)
### 3.1 Layout (in this order; golden-tested)
```python
# Generated by pyguibud-uic 0.1.0 (format 1) from 'hello.ui'. Do not edit: changes are lost on regeneration.
# Requires Python >= 3.10 and ttkbootstrap >= 2.2, < 3. This module does not import PyGUIbud.
from __future__ import annotations

# --- support: identical in every generated module (pyguibud-uic format 1) ---
import base64 …                              # the support region's own imports (§1, §4)
…                                            # _support.py text between its BEGIN/END markers
# --- end of support ---

_DOCS = (('hello', 'en_GB', 'examples/locale'),)   # (i18n_domain, source_locale, locale dir relative to this file)
_HANDLERS = ('on_greet', 'on_quit')               # sorted, unique, every document
_THEME = 'flatly'
_IMG_0 = ('iVBORw0K…'                              # one constant per (document, image id); base64 in 76-char chunks
          '…')

class Ui_Main(_Ui):
    """Generated interface; build it with setup_ui()."""

    def _build(self) -> None:                     # straight-line, pre-order (runtime §3 build order)
        s = self
        …
    def _component_0(self, s: _Scope, parent: tkinter.Misc) -> tkinter.Misc:   # one per (file, component)
        …

if __name__ == "__main__":                        # preview: python hello_ui.py [--lang de_DE]
    _preview(Ui_Main)
```
- The file name in the header is `ascii(os.path.basename(path))`. That is the only path text in the output; no absolute path ever appears. The version is `pyguibud.__version__`, and golden tests normalise that one header line with a regex (decision C6).
- **Class name:** `Ui_` + the main window id with its first letter upper-cased (`main` → `Ui_Main`, as in ADR-003). With no main window, the file stem is used instead: non-`[A-Za-z0-9_]` characters → `_`, and a leading digit gets an `_` prefix after `Ui_`. The result must pass `str.isidentifier()` and must not be a keyword; otherwise `codegen.unsafe_name`.

### 3.2 Why this shape (options weighed)
| Option | Readability | Size (hello) | Single Tk-mapping source | Verdict |
|---|---|---|---|---|
| A. Pure straight-line (pyuic) | best | large: mnemonics, clipping, liveness and retranslate repeated inline | no: the logic is re-written in templates | ✗ |
| B. Data tables + a vendored mini-loader | poor: the build is opaque | small | no: a second `_tk.py` | ✗ |
| **C. Support code (fixed, tested) + straight-line build** | good: one line per widget, option and placement | ~300 lines of support + ~4 lines per widget | **yes**: mapping decisions are made at generation time by `_tkmap`/`core.keys`; only runtime-only logic (mnemonic split after translation, clipping, translators, liveness) lives in `_support.py`, and hypothesis proves it equal to `core.keys.split_mnemonic`/`_tkmap.clip_text` | ✓ |

### 3.3 `setup_ui` (amends ADR-003; decision C2)
```python
def setup_ui(self, master=None, handlers=None, *, strict=True, lang=None, localedir=None, translator=None) -> None
```
- The positional order (window first, then handlers) is ADR-003's. The first parameter has **`load_ui`'s `master` semantics**: `None` → create `ttkbootstrap.App` (the own root; the theme is applied); a live widget → the main window becomes a `Toplevel` of it, and the theme is not changed.
- **Pre-Tk phase:** no Tk object is created before all of these checks pass, in this order:
  1. argument types → `TypeError`/`ValueError` (same texts and the same `lang` regex as runtime §2.1);
  2. a second `setup_ui` call → `UiError("runtime.already_built")`;
  3. resolve `_HANDLERS` with runtime §4.1's rules (Mapping → `.get`, else `getattr(handlers, name, None)`, a raising lookup counts as missing, the value must be `callable`); strict and missing → `UiError("runtime.missing_handlers", names=sorted)`, non-strict → log each;
  4. build the translators (§4.3);
  5. `master` is not None and not a live `tkinter.Misc` → `TypeError`;
  6. `master is None` and a live root exists → `UiError("runtime.root_exists")`.
- **Build phase:** the same steps as runtime §3, 1–11. `TclError` while creating `App` → `UiError("runtime.no_display")`. Any other exception → destroy everything created, then `UiError("runtime.build_failed")` from the cause.
- **Invariant (tested):** after a failed `setup_ui` there is no new root, no new toplevel and no `Style` singleton.

### 3.4 Members (exactly the pinned surface)
- Public: `setup_ui`, `retranslate`, `show`, `run`, `destroy`, `vars`, `widgets`, `windows`, plus one attribute per id after `setup_ui`.
- Every other member, attribute and method (on `_Ui` and `_Scope`) starts with `_`. **`RESERVED_IDS` is unchanged** (§9).
- `retranslate`/`show`/`run`/`destroy`, liveness, all-or-nothing retranslation, `select` arming, clipping and mnemonics follow runtime §2.2, §3, §4 and §6 to the letter.
- Include scopes are `_Scope` instances (`vars`, `widgets`, `windows == {}`). Same-file components share the host `vars`; external components get fresh variables per include (runtime §7.2).

### 3.5 `UiError` in the generated module (decision C3)
```python
class UiError(RuntimeError):
    def __init__(self, code: str, message: str, names: tuple[str, ...] = ()) -> None
    code: str; names: tuple[str, ...]
```
- It is defined in the support code, so each generated module has its own class; `except module.UiError` is documented.
- `code` uses runtime's strings (`runtime.destroyed`, `runtime.unknown_window`, `runtime.missing_handlers`, `runtime.root_exists`, `runtime.no_display`, `runtime.build_failed`, plus the new `runtime.already_built`).
- Messages are **fixed en-GB, not translated**: they are developer-facing, and the pyguibud catalogue is unavailable. They use the same wording as runtime §2.4. "Never set up" uses `runtime.destroyed` with "This interface is not built or has been destroyed."
- Log warnings (`logging.getLogger(__name__)`) are en-GB with the same texts as runtime §2.4: `handler_missing`, `catalogue_missing`, `unknown_theme`, `theme_ignored`, `bootstyle_ignored`, `shortcut_duplicate`, `text_clipped`. Extension fallbacks and invalid `bootstyle` values are reported **at generation time** (stderr, translated); the generated code only logs `bootstyle_ignored` when ttkbootstrap rejects a value at runtime.

### 3.6 Deliberate deviations from `load_ui` (documented in the module docstring of `_support.py`)
| Topic | `load_ui` | Generated |
|---|---|---|
| Error class | `pyguibud_runtime.UiError`, translated | the module's own `UiError`, en-GB |
| Bad `master` | `runtime.backend_unavailable` | `TypeError` (API misuse) |
| Pseudo-locale `en_XA` | `PseudoTranslations` | **not supported** (decision C5): an ordinary code, so no catalogue → identity + warning; pass `translator=` instead |
| Catalogue folder | `<each .ui dir>/locale` | the same folder, as a path relative to the generated file (§4.3) |
| Images | `PhotoImage(file=)` | embedded `data=` (§4.4) |
| Validation, extension fallback | at load time | at generation time |
| Runtime-owned strings (dialog buttons) | trimmed in Step 10 | none emitted (no button bar until Step 14) |

## 4. Support code (`codegen/_support.py`)
A real module, type-checked and linted. The generator copies the text between `# --- BEGIN SUPPORT ---` and `# --- END SUPPORT ---` (read in binary, CRLF → LF, so a Windows checkout cannot change the output).
- **The BEGIN marker sits above the import lines,** so the copied region carries its own imports. The emitter writes no import block of its own (one source for the imports). The `from __future__ import annotations` line and the module docstring stay outside the region; the emitter writes `from __future__` itself.
- **Ids are attached only through `_attach(s, "id", obj, window=False)`**, which sets the attribute and the `widgets`/`windows` mapping. The build code reads them as `s.<id>`. `_Scope.__getattr__` returns `Any`, as in `UiScope`, so the generated file passes mypy `--strict`.

### 4.1 Contents
- `UiError`, `_Scope`, `_Ui` (the public methods + `_begin`/`_live`/`_attach`/`_slot`).
- `_split_mnemonic`: a copy of `core.keys.split_mnemonic`.
- `_clip` (`_MAX_TEXT = 100_000`): written by the generator as a literal from `core.validate.MAX_TEXT_LENGTH`. A test asserts they are equal.
- `_check_lang`, `_resolve`, `_translators`.
- The wiring helpers `_command`, `_trace`, `_modified`, `_virtual`, `_bind`, `_shortcut`: each no-ops for an unresolved handler, and none is a lambda over a loop variable.
- `_create`: tries `bootstyle`, then retries without it.
- `_image`, `_preview`.

### 4.2 Rules for this file
- **No `_(`, `gettext(`, `pgettext(`, `N_(`, `NP_(`, `ngettext(` call with a literal argument.** `babel.cfg` extracts `src/**`, so such a call would leak into `pyguibud.pot`. Translators are called as `t.gettext(msgid)` with variables only. A test greps for this.
- No `eval`, `exec`, `compile`, `__import__`, `importlib`, `pickle`, `subprocess` or `os.system`.
- Handlers are looked up with `getattr(obj, name, None)` only inside `_resolve`, with `name` taken from `_HANDLERS`.

### 4.3 Translations (stdlib only)
- **Per document,** like runtime §6.1, cached per `(domain, dir, lang)`:
  - `translator=` wins;
  - an empty domain → `gettext.NullTranslations()`;
  - otherwise the `.mo` files are read directly with `gettext.find(domain, dir, [lang] or None, all=True)` and a `GNUTranslations` fallback chain (not `gettext.translation`, whose process cache would stop `retranslate()` from seeing recompiled catalogues);
  - a corrupt `.mo` → identity + `catalogue_missing`.
- `pgettext` exists from Python 3.8, which the ≥ 3.10 floor covers. An empty value is never passed to gettext.
- **Catalogue folder (decision C4):** for each document, the generator emits `os.path.relpath(<that .ui's dir>/locale, <output dir>)` as POSIX text. At runtime this becomes `os.path.join(os.path.dirname(os.path.realpath(__file__)), rel)`: both sides use the real path (symlinks, junctions and subst drives resolved; QA-11-02).
  - Different drives (`ValueError`) → `"locale"` (next to the module), with a generation warning.
  - `setup_ui(localedir=…)` overrides it for every document, as in `load_ui`.
  - This keeps the plan's UAT (`-o hello.py` at the repository root → `examples/locale`) working, without absolute paths.
  - Moving the generated file breaks the relative path; this is documented, and `localedir=` is the fix.
- **The user obtains the `.mo` file** with `pyguibud-uic --extract hello.ui -o hello.pot`, then `msginit`/`pybabel init` and `pybabel compile` (gettext or Babel, the user's choice). This is documented in the generated-module docstring and in the README in Step 21.

### 4.4 Images (decision C7)
- **Embedded.** The generator reads each resource file **once**, capped at `MAX_IMAGE_BYTES + 1` bytes; more → `codegen.image_changed`. It then re-checks **those bytes**, not the file again, with a new pure helper `core.files.probe_bytes(data: bytes, suffix: str) -> ImageProbe`, which factors out `_read_size` and `_gif_frame_size` (over `io.BytesIO`) and which `DiskFiles.probe_image` reuses. Status ≠ `ok` → `codegen.image_changed`. This closes the gap between R76's probe and the read. Only then does it emit `_IMG_n` as base64 text in 76-character chunks.
- Constants are numbered by first use in traversal order, **never** by `DiskFiles` key.
- At runtime: `tkinter.PhotoImage(master=root, data=<base64 str>, format=fmt)` for `png`/`gif`. For PPM/PGM: `data=base64.b64decode(...)` (bytes) with `format="ppm"`.
- Embedding avoids `-file`, so the stale Tcl std-handle problem (§5 notes) cannot occur, and the module is self-contained.
- **11b verification gate:** a `gui` test loads one PNG, GIF, P5 PGM and P6 PPM fixture each through `data=`. If PPM/PGM fails on the CI Tk 8.6, the fallback is that codegen transcodes PPM/PGM to PNG at generation time (stdlib `zlib` + `struct`, about 50 lines; trim item 2). It never falls back to `file=`.
  - **Result (11b, Tk 8.6.15, Windows):** PNG and GIF load from a base64 `str`; P5/P6 load from `base64.b64decode(...)` bytes (a base64 `str` is refused, as anticipated). **Gate passed, no transcoding** (`test_images_are_embedded_and_load_through_data`). ASCII P2/P3 fail in Tk with `data=` *and* `file=`, so codegen and `load_ui` behave alike; R76 now refuses P2/P3 (QA-11-07, §12.2).

## 5. Generation-time plan (`_plan.py`)
- **Instance tree:** built from `DiskFiles` exactly like runtime P5. Each distinct `(file key, component id)` gets a method `_component_<n>`, numbered by **first encounter in pre-order** (windows in document order, then children). Each include emits one call to its method, so the output stays linear in the number of distinct components. R53 already bounds the expansion.
- **Handler names:** sorted and unique across the whole tree → `_HANDLERS`.
- **Documents:** numbered by first encounter → `_DOCS` index. A text slot carries its document index.
- **Extensions:** `registry.resolve(class, "ttkbootstrap", fallback)` → the spec. A fallback gives a generation warning (`_M_FALLBACK`, so no new msgid).

## 6. Emitting rules (`_emit.py`) — injection safety
1. **Literal gate:** `lit(v)` accepts only `str`, `int`, `bool`, finite `float`, `None` and tuples of these, and returns `repr(v)`. Anything else → `TypeError`. **Every `.ui` string reaches the output only through `lit()`**, never through f-string or `%`/`format` interpolation into code, comments or docstrings.
2. **Identifier gate:** `ident(x)` requires `core.validate._ID_RE.fullmatch(x)`, `not keyword.iskeyword(x)` and `x not in RESERVED_IDS`, else `CodegenError("codegen.unsafe_name")`. These are explicit checks, not `assert`, so `-O` cannot strip them. Ids appear as code only in `s.<id>` attribute position. Locals are a fixed vocabulary (`s`, `w`, `top`, `bar`, `menu`, `frame`, `parent`, `root`, `v`), never named after an id.
3. **Handler names** must pass the `_ID_RE` + non-keyword check at generation time (else `codegen.unsafe_name`; this blocks `__class__`-style lookups even if a validator bug lets one through). They are emitted only as `lit()` strings (`self._command(w, 'on_greet')`), never as bare names.
4. **Tk sequences** come only from `tk_shortcut`/`tk_key_sequences`/`_tkmap`, already validated (R71/R72), and are emitted via `lit()`.
5. **No comment carries `.ui` content,** except the header file name through `ascii()`.
6. **Values:** props are converted by `PropertyDef.type` at generation time (runtime §8.4 effective-value rule, `_OPTION` renames), so the build code passes Python literals. Grid and pack keywords are the same set `_tk.py` passes, with the gap arithmetic (runtime §8.3) precomputed.
7. **Text slots:** `self._slot(doc, ctx, msgid, mnemonic, label, kind, target, extra)` with `kind ∈ {"title", "text", "text_u", "entry", "tab"}`, so no lambdas or closures are needed.
8. **Determinism:** document order everywhere; no `set` iteration without `sorted`; LF newlines; one trailing newline; no trailing spaces. Output = `"\n".join(lines) + "\n"`.

## 7. CLI contract (`pyguibud-uic`)
```
pyguibud-uic FILE... [-o OUT] [--force] [--lang CODE]     # generate (default mode)
pyguibud-uic --check FILE...                               # unchanged: behaviour, output, exit codes
pyguibud-uic --extract FILE... [-o OUT.pot] [--force]      # catalogue template; stdout without -o
```
- `--check` and `--extract` are mutually exclusive (argparse group). `-o`/`--force` with `--check` → usage error (`--force` is allowed with `--extract`).
- **Generate:**
  - `-o` only with exactly one input (usage error 2). Without `-o`, `default_output(path)` writes `<dir>/<stem>_ui.py`, where the stem has non-`[A-Za-z0-9_]` characters turned into `_` (so it is importable).
  - Reader warnings and findings are printed exactly as by `--check`. On success, stdout shows "{path}: wrote {output}".
  - **Refused (exit 1, nothing written), each reported as `OUT: error: …`:**
    - the output is the same file (`os.path.samefile`, else `realpath` + `normcase` without a Win32 namespace prefix; QA-11-13) as any input of the run or to any file of the include tree → `codegen.same_file` (even with `--force`);
    - the output was already written by this run (several inputs with the same default output) → `codegen.already_written` (even with `--force`);
    - the output is not a regular file (folder, device, Win32 device name such as `CON` or `nul.txt`); checked with `os.stat` + `S_ISREG`, never opened → `codegen.not_regular` (even with `--force`);
    - the output exists and does not start with `GENERATED_MARKER` and `--force` was not given → `codegen.not_generated` (decision C8);
    - an image or include path that is absolute or leaves the folder of its `.ui` file (R46/R47 warnings) and `--force` was not given → `codegen.outside_path` (`generate_python(..., allow_outside=False)`; QA-11-03). `--force` therefore means both "replace" and "accept outside resources";
    - a write failure (`OSError`) → `codegen.write_failed`.
  - **Atomic write:** a temporary file in the target directory, `newline="\n"`, UTF-8, then `os.replace`. The temporary file is removed on failure. The file is not marked executable.
- **Extract:** reads and validates every input (with `files=None`: no include or image I/O is needed), then merges them into one `.pot` (§8). Any read or validation error → exit 1 and no output. With `-o` the output passes the same refusals as generation (the inputs and their include trees → `codegen.same_file`; folders and devices → `codegen.not_regular`), and an existing file is replaced only if its first 4 KiB carry the `"Generated-By: pyguibud-uic` header line, else `codegen.not_generated` unless `--force` (QA-11-01); a `.po` target or a file with translations is refused as `codegen.translations` unless `--force` (QA-11-14). The write is atomic and stdout shows "wrote {output}".
- `--lang` sets the CLI's message language only. It never affects the output (§2).
- **Exit codes:** 0 = all files done (warnings allowed); 1 = any file failed to read, failed validation, was refused or failed to write (later files are still processed); 2 = usage.
- **Messages** (pyguibud catalogue, `N_` + `# Translators:`; printed as `<file>: error: <message>`, or `warning:`):

| Code | When | msgid (en-GB) |

| `codegen.read_only` | newer MINOR | "'{path}' was written by a newer PyGUIbud ({version}); update PyGUIbud to generate code from it." |

  In the generated module (en-GB, untranslated): `runtime.already_built` = "setup_ui() has already been called on this object."

## 8. `--extract` (`_pot.py`)
- **Entries:** one per unique `(msgctxt, msgid)`, from every `translatable="true"` prop with a **non-empty** value: window titles, menu, action and statusbar texts, widget props, page texts. They come in **traversal order**: windows in document order, then for each window its props, its menubar (pre-order), its statusbar and its widget tree (pre-order: props, then page text). `positions` is used **only** for the `#:` line: `positions.get(owner, "prop[<name>]")`, or `"page/prop[text]"` for pages. `None` (a node created by a migration) → no `#:` line.
- Multiple inputs are merged in argument order. A repeated key accumulates its references and its distinct comments. `Project-Id-Version` comes from the first input's domain, or from its stem if the domain is empty; characters outside `[A-Za-z0-9_.-]` become `_` (QA-11-10).
- **Comments:** `#.` lines from `comment`, split with `str.splitlines()`; each line is prefixed, so a comment can never inject a PO line.
- **References:** `#: <path>:<line>`, where `<path>` is relative to `base_dir` (the `-o` directory, else the CWD) in POSIX form. A cross-drive `ValueError` → the basename. A path containing whitespace is isolated between U+2068 and U+2069, as gettext ≥ 0.22 writes it and Babel reads it (QA-11-09); a path with a control character, a line or paragraph separator or an isolate character → no `#:` line.
- **Header:**

  ```
  # Translations template for <domain or stem>.
  #, fuzzy
  msgid ""
  msgstr ""
  "Project-Id-Version: <domain or stem>\n"
  "MIME-Version: 1.0\n"
  "Content-Type: text/plain; charset=UTF-8\n"
  "Content-Transfer-Encoding: 8bit\n"
  "Generated-By: pyguibud-uic <version>\n"
  ```

  There is **no `POT-Creation-Date`** (determinism); tests normalise the `Generated-By` line.
- **Escaping:** `\\`, `\"`, `\t`, `\r`, `\n`. A msgid containing `\n` is written in the multi-line form (`msgid ""` followed by one quoted line per segment). There is no width wrapping. Output in UTF-8 with LF newlines. To stdout it is written as bytes to `sys.stdout.buffer`, so a cp1252 console cannot break it.
- No runtime-owned button labels are extracted (no button bar until Step 14).

## 9. Reserved ids
`RESERVED_IDS` is **unchanged**. Every non-id public member of `Ui_<Name>` and `_Scope` is already in it, and everything else is `_`-prefixed. Module-level names (`UiError`, `_DOCS`, …) never clash, because ids are only attribute names. Keywords are already rejected (R-keyword); soft keywords (`match`, `type`) and builtins are valid attribute names. **Pinning tests:**
- `{n for n in dir(Ui_Main()) if not n.startswith("_")} == RESERVED_IDS`, on an instance **before** `setup_ui`, because `vars`, `widgets` and `windows` are instance attributes;
- `{n for n in dir(_Scope()) if not n.startswith("_")} == {"vars", "widgets", "windows"}`.

### 12.1 11b deviations (backend, 2026-10-06)
1. The support region also imports `contextlib`, `typing` (`Any`) and `warnings` (stdlib; `warnings` catches ttkbootstrap's bootstyle warnings as `_tk.py` does). The §1 list grows by these three.
2. `_tkmap` also receives `_DOUBLE` (used by `_ACTIVATE`) and the ttkbootstrap class table `_RENAMED`/`_CLASSES` (from `backends/ttkbootstrap.py`), so the class names codegen emits have one source. `_M_SHORTCUT`/`_M_CLIPPED` stay in `_tk.py`.
3. `CodegenError` msgids are plain en-GB strings in `codegen/_errors.py`, not yet `N_`/`NP_`-marked (so `pyguibud.pot` is unchanged); `codegen.invalid_document` picks the singular/plural text by `count`. **11c** marks them, adds `# Translators:` comments and updates the catalogues.
4. The generated class binds the module constants as class attributes (`_docs = _DOCS`, `_handler_names = _HANDLERS`, `_theme_name = _THEME`), so `_support.py` is a self-contained, type-checked module.
5. `_attach(scope, name, obj, window=False)` is a module function; `_Scope(share)` copies the host's variables namespace for a same-file include (same variable objects, like `load_ui`).
6. Components are numbered in build order (main windows, then dialogs; as `load_ui` builds them), and only images that are used are embedded, numbered by first use.
7. `runtime.build_failed` says "Building the interface Ui_<Name> failed: {reason}" (the generated module has no `.ui` path); "never set up" and "destroyed" share "This interface is not built or has been destroyed."
8. A file with dialogs only and `setup_ui(master=None)` is **refused** like `load_ui` (`UiError("runtime.no_main_window")`, raised in the pre-Tk phase, so no hidden root is created). The class carries `_has_main = False` only in that case (decision of the orchestrator, implemented in 11c).
9. `pyguibud.codegen.support_text()` is public (used by the tests and the 11d golden support-block check).
10. 11c: `GeneratedModule.sources` lists every `.ui` file of the module (input plus includes) for the CLI's same-file refusal; `CodegenError` msgids are now `N_`/`NP_`-marked (`codegen.invalid_document` is one `NP_` msgid) and `M_SAME_FILE`, `M_NOT_GENERATED`, `M_WRITE_FAILED` were added; `--force` with `--check`/`--extract` and `-o` with `--check` are usage errors.

## 13. Risks
- **Parity drift:** behaviour fixed in `_tk.py` later has to be mirrored in `_support.py`/`_emit.py`. Mitigation: `test_parity.py` is mandatory for any change to `_tk.py`; the shared tables live in `_tkmap`.
- **Tk `-data` for PPM/PGM:** unverified; gated in 11b with a stated fallback.
- **Large embedded images:** up to about 21 MiB of source per 16 MiB image (R76 cap). This is acceptable for v0; a `--images=files` option is a later idea.
- **ttkbootstrap 3.x:** the generated code pins the 2.x API in its header. A future format bump regenerates.
- **The relative locale path** breaks when the module is moved; documented, and `localedir=` fixes it.
